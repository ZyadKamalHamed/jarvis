## Gotchas discovered tonight (save yourself the hours)

- `claude -p --resume` sessions are cwd-scoped and race if parallel: the server serialises asks through one promise chain; keep it that way.
- Session JSON: parse `result`, `session_id`, `is_error` from `--output-format json`. A failed resume must null the stored session id so the next ask starts fresh (already implemented).
- Project `.mcp.json` servers do NOT load in `-p` without user-scoped pre-approval (`enabledMcpjsonServers` in `~/.claude/settings.json`, not the repo settings). Each stdio MCP costs 1 to 3 seconds per invocation: keep the ask path MCP-free.
- Permission rules: `Write(drafts/**)` style paths anchor at the project; `Read(**/.env)` deny patterns protect secrets from the head agent (already in `.claude/settings.json`).
- Graph consumer accounts: incremental consent works; one new device-code run with `["Mail.Read","Mail.ReadWrite","Mail.Send"]` upgrades the cached token. MSAL adds reserved scopes itself; passing openid/profile explicitly makes it throw.
- Tailscale on this Mac is now logged in under the ZyadKamalHamed account, which is a DIFFERENT tailnet from the old zyadschneider24 one (tail70b7c5.ts.net). The OpenClaw Google Chat funnel config from memory targets the old tailnet and is currently dead. Fixing it means either re-login with the Google account or re-running the funnel setup for the new hostname AND updating the Google Chat app's audience URL (see the openclaw-g-chat-config skill notes).
- `tailscale serve` needed one-time tailnet enablement (admin URL); if serve status looks empty, check that first.
- RESOLVED 10 Jul: the scheduled agents now run via launchd (`deploy/com.zyad.jarvis.daily.plist` 7:30am, `.evolve.plist` 9:30pm, wrapper `bin/run-job.sh`), verified end to end headlessly. The Claude-app registration path is dead; do not resurrect it.
- LESSON 11 Jul: launchd fires a missed calendar job on wake, but if the Mac wakes without wifi the claude call dies (ConnectionRefused) and nothing retried. `bin/run-job.sh` now waits up to 10 minutes for api.anthropic.com before starting, and `deploy/com.zyad.jarvis.catchup.plist` sweeps every 30 minutes running whatever the day still owes (daily after 7:30, evolve after 21:30, per-job locks prevent double runs). Also covers full shutdowns, which launchd calendar jobs never replay.
- Headless `claude -p` IGNORES `.claude/settings.json` permissions until the workspace is trusted: `projects["/Users/Zyad/Coding/JARVIS"].hasTrustDialogAccepted: true` in `~/.claude.json` (set on this Mac 10 Jul; the home laptop will need it too, or one interactive claude session in the repo).
- LESSON 14 Jul (supersedes the 10 Jul calendar note): macOS 26 never shows the Calendars prompt for osascript at all, in any Terminal. The request is attributed to Terminal, whose Info.plist has no NSCalendarsFullAccessUsageDescription, and TCC auto-denies requests with no usage string, silently. EventKit access therefore lives in `bin/CalendarHelper.app`: an osacompiled JXA applet (source `bin/calendar-helper.jxa`) with proper usage strings and a stable bundle id, built on demand by `bin/build-calendar-helper.sh` (gitignored product; each machine builds its own and gets its own prompt). `calendar.mjs` invokes the applet, parses its stdout JSON and keeps the honest denied state. A stuck denial re-arms with `tccutil reset Calendars com.zyad.jarvis.calendarhelper`.
- LESSON 15 Jul: agent-authored free text on work-visible surfaces is a standing leak class. The morning run named application targets (Westpac, Siemens, AIOS staleness) in the metrics run `note` and in `system.json` notes on non-career pipelines, none of which tripped the then-current banned list. Three-layer fix: work mode sheds the metrics note entirely (day summaries are unclassifiable free text, same rule as the inbox), surviving system notes are scanned and degrade to the bare status when dirty, and the employers he applies to became banned words themselves (westpac, siemens). The daily-run guardrails now say it plainly: work-visible free text never names employers, applications or career artefacts. When adding any new served field, ask first: who writes it, with what in scope, and does it travel in work mode?
